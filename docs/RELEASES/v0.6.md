# v0.6 — Server-side LLM world-spec compiler

## Included
- New same-origin `POST /api/world-spec` serverless endpoint calling the OpenAI Responses API from the server.
- Provider response constrained with strict JSON Schema and revalidated by the app's own versioned world-spec validator before any result is returned.
- Prompt length/body limits, bounded accepted controls, supported preset enums, same-origin checks for browser requests, no-store responses, a per-warm-instance burst limiter, timeouts, and explicit provider error handling.
- The UI now offers separate **Ask AI to compile** and **Compile locally** actions. It never silently substitutes local rules for a failed AI request; users can inspect the JSON and explicitly apply it afterward.
- Server-side configuration uses `OPENAI_API_KEY`; optional `OPENAI_MODEL` defaults to `gpt-5-mini`. The key must never be placed in browser code, GitHub files, or a public-prefixed environment variable.
- The API sets `store: false` on the Responses request and does not log prompt text in application code.

## Activation requirement
The v0.6 source is deployed to the existing production alias. Vercel's environment listing returned no variables and zero hidden Production variables, so add `OPENAI_API_KEY` under the DOTS Living World project's **Settings → Environment Variables**, target **Production**, then create a new production deployment or redeploy the current version. A model can also be selected with the optional `OPENAI_MODEL` variable. The endpoint's live model response has not yet been smoke-tested.

## Explicit limitations
- A provider credential, usable API billing/quotas, and a production smoke test are required before claiming the live AI path is active.
- The in-memory rate guard is per warm function instance, not a durable global quota; anonymous public launch needs a shared rate-limiter and cost budget.
- This endpoint compiles declarative world settings only. It cannot generate or execute model code, and the server validator remains authoritative.
- Prompts are sent to OpenAI for processing when Ask AI is used. `store: false` is requested, but third-party processing and account-level data controls remain subject to the provider's terms and policy.
- NCA weights remain initialized and untrained, while voxel inhabitant behavior remains scripted.

## Acceptance checks
- Automated tests verify prompt bounds, settings normalization, strict schema constraints, provider request mode, output extraction, output validation, refusals/incomplete responses, and burst-limit behavior.
- CI verifies the frontend/API source entry points and the visible separation between AI and local compilation.
- Live model-backed acceptance is pending verification of the Production API key and an actual provider request.
